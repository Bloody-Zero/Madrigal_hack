# Лаборатория протоколов — MVP 0.1

Локальное приложение для исследования незашифрованного бинарного обмена по TCP/IPv4.
Загружает PCAP/PCAPNG, восстанавливает направленные потоки, применяет изменяемые
правила, сохраняет основания гипотез и переносимый проект. Это первая рабочая сборка,
а не подтверждение полного выполнения всех требований хакатона.

## Быстрый запуск: Linux

Требуются Python 3.11+ (проверено на 3.12) и TShark (проверено на 4.2.2).
Весь архив нужно распаковать. Команды выполняются из папки `protocol_lab`.

```bash
bash install.sh --system-tools
bash run.sh --project ./my-research
```

`--system-tools` использует sudo и apt-get: устанавливает Python/venv/tk и TShark.
Этот режим предназначен для Ubuntu/Debian. Если системные инструменты уже установлены:

```bash
bash install.sh
```

Приложение работает по адресу http://127.0.0.1:8000. Лаунчер открывает браузер.
Без `--project` предлагает выбрать папку через системный диалог, если доступен Tk.
В среде без графического экрана используется папка `research-project`.
Остановка сервера: Ctrl+C в терминале. Закрытие вкладки сервер не останавливает.
Системные привилегии нужны для установки компонентов, но не для разбора файлов.

## Windows

Установите Python 3.11+ с Python Launcher и Wireshark с компонентом TShark.
Для чтения сохранённых файлов захват через Npcap не требуется.
В PowerShell из папки приложения:

```powershell
.\install.ps1
.\run.ps1 --project C:\Research\experiment
```

Если локальная политика запрещает выполнение скриптов, используйте разрешённый
администратором способ запуска либо выполните команды Python вручную.
TShark ищется в PATH, переменной `TSHARK` или стандартном пути установки Wireshark
в скриптах Windows. На Windows эта сборка не тестировалась. Готового `.exe` пока нет:
поставляются исходный лаунчер и скрипты. Перед упаковкой потребуется отдельная проверка
на целевой Windows-машине.

## Первый сценарий: 10 минут

1. Добавьте `examples/training.pcap` и `examples/additional.pcap`.
2. Нажмите поток с данными; изучите HEX, выберите байт и нажмите номер пакета.
3. В «Журнале» импортируйте `examples/actions.csv`. Кнопка «Ближайший обмен»
   показывает ближайший сегмент по времени, а не доказывает причинную связь.
4. В «Правилах» выбран профиль `AA55 + тип + длина тела`. Тело имеет переменную длину.
5. Добавьте поле `value`: offset 5, тип uint16, порядок big. Изучите смысл по примерам:
   это поле предназначено для команды 1; универсального смысла для команды 2 у него нет.
6. Нажмите «Все с данными», затем «Проверить корпус». Базовый профиль разбирает
   3 сообщения в первой записи и 2 в дополнительной. Дополнительная содержит
   новое значение 300 и тело длиной 260 байт.
7. Ошибочная гипотеза для проверки: замените ширину поля длины 2 на 1. Запустите
   проверку — появятся конкретные нарушения. Верните 2 и повторите.
8. Выделите диапазон: клик на начало, Shift+клик на последний байт. Сохраните
   наблюдение или гипотезу с основаниями. Конец диапазона не включается.
9. В «Проверках» скачайте HTML-отчёт и полный JSON результатов. Отдельно доступны
   JSON текущих правил и ZIP всего проекта.
10. Остановите приложение, распакуйте проект в новую папку и передайте её в `--project`.

Все файлы examples — **синтетические пакетные фикстуры**, не захват реального
оборудования. Они нужны для воспроизводимых проверок. Корпуса организаторов пока нет.

## Возможности первой версии

- Ethernet (включая разбор VLAN-оболочки), TCP/IPv4, PCAP и PCAPNG одного интерфейса.
- Соединения выделяет TShark; номера TCP-сессий имеют смысл только внутри источника.
- Два направления; порядок по sequence numbers; одинаковые повторы не удваивают байты.
- Пропуски, усечение, конфликты, отсутствие начала и неустановленные роли видны.
- Политика перекрытий: first-observed. Конфликтующие байты не интерпретируются.
- Проверка TCP checksum включена; предупреждение не удаляет пакет. Возможен offloading.
  В диагностике показывается исходный числовой статус TShark: 0 bad, 1 good,
  2 unverified, 3 not present (конкретный набор зависит от версии).
- Связь диапазона потока с пакетами и смещениями в исходных кадрах.
- Поиск HEX в известных однозначных байтах, позиционное сравнение диапазонов.
- Правила fixed/length, целые числа, float32, UTF-8 и байты, equals/min/max.
- Неописанные области и неохваченные данные сохраняются в результатах.
- Журнал действий из CSV; гипотезы и наблюдения привязаны к источнику и диапазону.
- Автосохранение валидных правил, заметок, действий и завершённых проверок.
- Фоновые задачи с отменой; отменённая проверка не заменяет последнюю завершённую.
- Экспорт ZIP, HTML, JSON и применение того же движка из CLI.

## Правила: пример

```json
{
  "name": "Пример заголовка длиной 5 байт",
  "framing": {
    "mode": "length", "offset": 3, "width": 2,
    "endian": "big", "add": 5, "min_size": 5, "max_size": 65541
  },
  "fields": [
    {"name": "marker", "offset": 0, "type": "bytes", "size": 2, "equals": "aa55"},
    {"name": "command", "offset": 2, "type": "uint8"},
    {"name": "body", "offset": 5, "type": "bytes", "size": "rest"}
  ]
}
```

Все смещения полей считаются от начала сообщения. `size: "rest"` означает остаток
сообщения. `start_offset` верхнего уровня позволяет явно пропустить начало потока.
Для length полный размер сообщения = значение поля + add; add может быть отрицательным.
Для fixed используется `{"mode":"fixed","size":7}`. Типы чисел:
uint8/16/32, int8/16/32, float32. Порядок по умолчанию big.
bytes выдаёт HEX в нижнем регистре; equals для bytes задаётся без пробелов, например aa55.
Если границу невозможно установить, остаток не угадывается. Успешный разбор структуры
не устанавливает назначение поля. Семантические утверждения фиксируются в журнале.

## CLI и перенос проекта

Остановите приложение перед открытием того же проекта через CLI. Блокировка не даёт
двум процессам одновременно записывать один проект.

```bash
.venv/bin/python -m lab.cli check --project ./my-research \
  --capture examples/additional.pcap --rule rules.json --direction 0
```

`rules.json` — скачанный или собственный файл. Можно указать относительный путь к
версии внутри проекта: `interpretations/HASH.json`. Без `--capture` проверяются
потоки существующего проекта. Без `--direction` выбираются оба направления.
Можно явно задавать ID через повторяемый `--stream`.

Код выхода: 0 — только ok/not_applicable; 2 — есть нарушения или неохваченные данные;
1 — ошибка запуска/входных данных. Все результаты сохраняются в `runs/ID.json`.

Каталог проекта: `project.json`, `sources`, `cache`, `interpretations`, `runs`,
`reports`. Журналы хранятся в project.json. Кеш входит в текущий экспорт и нужен для
открытия проекта версии 0.1. Исходники проверяются по SHA-256 перед запуском проверки
и экспортом. Не редактируйте файлы sources вручную.

Правила, источники и настройки обработки фиксируются в результате. Изменённые правила
делают прежнюю проверку устаревшей. Смена фрейминга не перепривязывает заметки к новым
сообщениям: они остаются на прежнем диапазоне потока с исходными пакетами.

## Реальный TCP-стенд

`tools/live_demo.py` реализует TCP-клиент и эхо-устройство с учебным бинарным форматом.
Чтобы получить запись в области Ethernet из ТЗ, используйте две VM/машины или Linux
veth-пару. Сначала начните захват на Ethernet-интерфейсе, затем запустите:

```bash
python tools/live_demo.py server --host SERVER_IP
python tools/live_demo.py client --host SERVER_IP > actions-raw.csv
```

Сервер завершится после одного клиента. Для захвата можно отдельно использовать
`tshark -i INTERFACE -f 'tcp port 9000' -w live.pcapng`; требуются права захвата.
Приложению-анализатору эти права не нужны. Для импорта действий добавьте столбец
source с именем live.pcapng. Захват loopback может иметь другой канальный тип;
нельзя просто переименовать его или объявить Ethernet. Стенд не является обязательным
для работы программы. На этой сборке реальный сетевой захват ещё не проверен.

## Явные ограничения 0.1

- Нет автоматического открытия структуры протокола, системы плагинов и произвольных скриптов.
- Нет расшифровки, UDP, IP-фрагментации, IPv6-разбора, нескольких точек наблюдения.
- Нет условных схем по коду команды и сложных вложенных/повторяющихся структур.
- Маркер проверяется как поле; автоматической ресинхронизации после потери границы нет.
- Журналы действий: CSV, не произвольный JSON; заметки добавляются через UI,
  редактирования/удаления заметок в интерфейсе пока нет.
- При недоступном поле длины остаток отмечается неразобранным. Для продолжения можно
  явно выбрать start_offset в новой интерпретации.
- Сырые пакеты с недоступным TCP-заголовком отражаются диагностикой; подробный просмотр
  их байтов остаётся в исходной записи и доступен через Wireshark.
- Повторное открытие проекта требует поставляемого кеша; автоматической перестройки
  отсутствующего кеша пока нет. Смена версии TShark требует отдельной повторной сверки.
- Проект открывается лаунчером; смена проекта без перезапуска и готовый exe не реализованы.
- Полная нагрузка ТЗ 100 МиБ / 250 000 пакетов / 1000 соединений / 100 000 сообщений
  пока не сертифицирована. Защитные пределы: 100 МиБ на источник, 250k пакетов,
  1000 соединений в источнике, 16 МиБ диапазона одного потока и 128 МиБ суммы диапазонов
  источника, 1 МиБ на сообщение, 100k результатов проверки. Превышение явно диагностируется.
- Арифметика sequence numbers рассчитана на диапазон менее половины пространства 32 бит;
  очень длинные сессии за пределами защитного диапазона не поддерживаются.
- Шифрование и роли неизвестного соединения не угадываются. HTTP/TLS в payload не
  превращают его в описанный протокол устройства автоматически.

Схема модулей и соответствие ТЗ: `docs/ARCHITECTURE.md`.
Зависимости закреплены для воспроизводимости. Перед реальным развёртыванием проверьте
их доступные обновления; это локальный хакатонный прототип.
