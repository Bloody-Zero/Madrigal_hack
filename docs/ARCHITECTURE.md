# Архитектура 0.1

## Границы

Локальная лаборатория неизвестного незашифрованного прикладного протокола поверх TCP/IPv4.
Основной вход: Ethernet PCAP/PCAPNG одного интерфейса, без IP-фрагментации.
Подготовленные правила относятся к учебному формату и не являются описанием корпуса
организаторов. Автоматическое угадывание протокола не заявляется.

| Файл | Ответственность |

| lab/static | Интерфейс без CDN и сборщика |
| tools/make_examples.py | Синтетические Ethernet-фикстуры |

| tools/benchmark.py | Воспроизводимое измерение выбранного объёма |

## Обработка

1. Источник копируется в sources с именем на основе SHA-256. Точный повтор не создаёт
   второй набор данных. Разные файлы не объединяются по адресам или номерам потоков.
2. TShark читает файл без изменения и выдаёт исходные кадры, TCP-поля и ID сессии.
   Используются -n, raw sequence numbers, включённая проверка checksum и отключённая
   прикладная TCP-десегментация. Версия TShark записывается в источник.
3. Адаптер проверяет канальную оболочку, длины IPv4/TCP и отсутствие IP-фрагментации.
   Исходные сырые TCP-кадры сохраняются в кеше вместе с номерами пакетов.
4. Потоки сгруппированы по источнику, экземпляру сессии TShark и направлению.
   Без видимого SYN роли неизвестны. Два независимых направления никогда не склеиваются.
5. Байты упорядочиваются по sequence numbers. Сохраняются маски known и conflicts.
   Внутренние нулевые заполнители не являются наблюдаемыми данными: UI показывает ??,
   поиск игнорирует их, движок не извлекает из неполных сообщений значения.
6. При конфликте выбран first-observed, но конфликтный диапазон явно помечен и не
   интерпретируется. Все соответствующие пакеты остаются в происхождении данных.
7. Правило выделяет сообщения и читает поля. Ошибки и неописанные диапазоны входят в результат.
8. Завершённая проверка публикуется отдельно; частичная/отменённая не выдаётся за завершённую.

## Идентичность и происхождение

Поток: SHA-256 источника + номер экземпляра сессии + направление. Диапазоны [start,end)
относятся к базе sequence number доступного потока, указанной в его метаданных.
Если SYN отсутствует, база не объявляется началом исходного соединения.

Происхождение: номер пакета, диапазон в потоке, смещение TCP payload внутри кадра,
временная метка наблюдения. Перекрывающиеся записи сохраняются, включая повторные.
Наблюдение хранит эти основания и не зависит от номера сообщения в текущем фрейминге.

## Правила и воспроизведение

Канонический JSON хешируется с сортировкой ключей. Запуск содержит снимок правил,
выбранные потоки, хеши источников, настройки обработки, версию движка, сводку и строки.
Источник сверяется перед проверкой и экспортом. Старый результат отличим после изменения
правил. Одновременно проект записывает только один процесс (advisory file lock).

Файлы проекта используют относительные пути. Кеш включается в экспорт; его автоматическое
восстановление в версии 0.1 не реализовано. Абсолютный путь проекта показывается в UI,
но не является зависимостью сохранённых ссылок на источники.

## Отзывчивость

Одна тяжёлая задача на проект. Импорт и проверки выполняются через ThreadPoolExecutor;
HTTP обслуживает просмотр доступных данных. UI опрашивает статус. Отмена импорта
завершает дочерний TShark, отмена разбора проверяется между единицами обработки.
Прогресс показывает этап и счётчик, а не фиктивный процент. Операции подготовки JSON,
хеширования и атомарной записи не прерываются посреди записи.

В 0.1 кеши хранятся в памяти по мере открытия, а исходные TCP-кадры представлены HEX.
Для больших корпусов понадобится измерение, затем возможен переход к индексам и ленивому
чтению. Максимальную нагрузку ТЗ пока нельзя считать проверенной.

## Интерфейс и ограничения поверхности

API обслуживается на 127.0.0.1, имена Host проверяются. Для изменяющих запросов требуется
токен текущего сеанса, CORS не включён. Все тексты источников/заметок экранируются.
Пользовательские правила не выполняют Python, shell или JavaScript. Вызов TShark — список
аргументов без shell. Пути из проекта проверяются на выход за его каталог.

## Соответствие требованиям

| Требование | Реализация 0.1 | Остаток/границы |
|---|---|---|
| R1 | Импорт, потоки, повторы, пропуски, конфликты, provenance | Полный исходник доступен; повреждённые до TCP кадры в UI представлены диагностикой |
| R2 | HEX, поиск, сравнение, журнал действий, ближайший сегмент | Позиционное сравнение; нет сложного выравнивания/статистических предложений |
| R3 | Правила fixed/length, переменные данные, значения, неизвестные области | Нет условных схем и сложных вложенных форматов |
| R4 | Выбранный корпус, все статусы, контрпримеры, повторный запуск | Без автоматической ресинхронизации неизвестной границы |
| R5 | Источники, правила, журналы и проверки, ZIP, перенос | Требуется кеш; Windows не проверена |
| R6 | HTML, JSON, CLI, примеры с ожидаемым результатом | Полезность на настоящем корпусе организаторов ещё не проверена |
| Нефункциональные | Offline UI, фоновые задачи, отмена, защитные пределы | Малый benchmark выполнен; полный профиль и среда 4 vCPU/8 ГиБ не подтверждены |

Строка таблицы описывает реализованные возможности; это не протокол приёмки от организаторов.
